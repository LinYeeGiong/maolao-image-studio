# 16 张参考图与站内弹窗设计

## 目标

让每一轮图片编辑支持新上传 1–16 张参考图，同时保留无参考图文生图和单张历史生成图继承能力。删除确认与对话重命名全部使用站内 UI，不再调用浏览器原生 `confirm` 或 `prompt`。

## 数据流

- 前端使用 `File[]` 保存本轮新上传图片，文件选择器开启 `multiple`，累计数量严格限制为 16。
- 提交时，每张图片以本地表单字段 `images` 重复追加。若本轮没有新上传图片，仍可提交一个 `source_image_id` 继承历史生成图。
- 后端同时兼容旧字段 `image` 和新字段 `images`，合并后校验总数不超过 16。
- 每张上传图片继续写入现有 `images` 表，`kind='reference'`，使用 `position` 保存顺序，因此不需要数据库迁移。
- 发往 MaolaoAPI 时，单图使用文档现有的 `image` 字段；多图按 OpenAI 数组格式重复发送 `image[]` 字段。必须使用 multipart tuple 列表，避免字典覆盖同名字段。

## 前端交互

- 输入区上方用紧凑缩略图网格展示全部参考图，显示 `已选择 X / 16`，每张可单独删除。
- 对话消息中展示该轮全部上传参考图，而不是只展示第一张。
- 超出 16 张、请求失败等信息使用现有站内错误条。
- 删除对话使用危险操作确认 Modal；重命名使用带输入框的 Modal。遮罩、取消按钮、关闭按钮均可退出，确认按钮执行原操作。

## 错误与兼容

- 空文件、非图片文件、超过 16 张均返回 HTTP 422，并给出中文错误。
- 任一保存或数据库操作失败时，清理本轮已经写入的所有临时参考图文件。
- 旧版单图前端仍可通过 `image` 字段调用后端。
- MaolaoAPI 是否实际支持 16 图仍取决于其上游代理；本项目按 OpenAI 兼容请求格式发送并保留上游错误。

## 验证

- 后端单元测试覆盖：无图 JSON 请求、单图 `image`、多图 `image[]`、16 张边界。
- 前端执行 TypeScript/Vite 构建，确保多文件状态、FormData 和 Modal JSX 均通过类型检查。
- 搜索生产前端，确认不存在 `window.confirm`、`window.prompt`、`window.alert`。
